## 2024-07-01 - Inconsistent Output Escaping (XSS)
**Vulnerability:** Found multiple Stored Cross-Site Scripting (XSS) vulnerabilities in `bills.php`. Several fields retrieved from the database (e.g., `buyer_company`, `buyer_address`, `item_name`) were being echoed directly into the HTML without being properly escaped. While some files or lines used `htmlspecialchars()`, many did not, indicating a lack of consistent escaping practices across the application.
**Learning:** The application uses PDO prepared statements for database writes, which protects against SQL Injection. However, reading from the database and rendering the data on the front end does not automatically ensure safety. An inconsistent application of output escaping leaves the application vulnerable to XSS.
**Prevention:** Always escape data before rendering it in the UI using `htmlspecialchars()` for HTML contexts. Establish a clear, codebase-wide convention for handling dynamic output to ensure consistent application of XSS protections. Consider using a template engine (like Twig or Blade) that provides automatic escaping by default, or create a helper function that escapes variables before output to reduce the risk of human error.
